# 001/01 — Detection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Each ingest run can record one notification row per new invoice, due-soon invoice and big story, exactly once; existing data counts as sent.

**Architecture:** A pure `plan_notifications(invoices, stories, known_keys, today, enabled)` returns new rows from plain facts; `record_notifications(session, now)` reads the facts and keys from the database and inserts the rows. The table and the launch baseline come in one migration (autogenerated table, hand-written RLS and baseline insert).

**Spec:** [../README.md](../README.md), task [01-detection.md](01-detection.md).

## Global Constraints

- Keys: `invoice_new:<invoice id>`, `invoice_due:<invoice id>`, `news:<news item id>`; unique.
- Statuses `pending`, `sent`, `failed`, `skipped`; kinds `invoice_new`, `invoice_due`, `news_big`.
- Dates in `settings.email_timezone` (Europe/Berlin). Due soon: open, `0 <= due_date - today <= 3`.
- Texts exactly as in the spec. Amount as `€49.90` for EUR, else `49.90 USD`; date as `24 Oct`.
- Invoices that arrive already `paid` get a `skipped` `invoice_new` row (ruling: nothing needs the owner).
- News text until 001/02: `📰 {first title}` + newline + `TLDR: {url} · Alpha Signal: {url}` (only the sources present).
- `enabled` = `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` and `APP_URL` all set (settings added here, ruling: 001/01's skipped rule needs them). Disabled → every new row `skipped`.
