# 002/05 — Web search in the News agent: implementation plan

Task: [05-web-search.md](05-web-search.md). Spec: [README](../README.md), Decisions and Design.

- **Agent:** `get_agent(*, web_search: bool)`, cached per flag (`lru_cache(maxsize=2)`), so the two agents are separate objects and tools can't leak between users. `run_news_agent` passes `web_search=not is_demo_user(deps.user_id)`. With web search: `capabilities=[NativeTool(WebSearchTool())]` and `model_settings=OpenAIResponsesModelSettings(openai_include_web_search_sources=True)`. PydanticAI merges an agent's settings over the model's, so anything `chat_model()` sets later is kept. Without: exactly today's agent and instructions.
- **Instructions:** a new `web_instructions.md`, appended only for the web agent, so a demo agent's prompt stays as it is: newsletters first, search only for missing details, never for briefings, say which part came from the web, and how to fill `web_citations`.
- **Output:** `NewsAnswer.web_citations: list[WebCitationRef]` (`url`, `title`, `citation_index`, `excerpt`), separate from `citations`, so item citations keep their type and their checks. `citation_index` is shared across both lists, as the database's unique constraint needs.
- **Markers:** `strip_citation_markers` runs as a field validator on `answer`, excerpts and titles, so no path can store or show a marker.
- **This turn's URLs:** `news_assistant/web_sources.py` reads `run.new_messages()`: sources from `web_search` returns and the URL of `open_page` calls. Other action types are ignored. The keys go in `deps.web_urls`.
- **Grounding:** `normalize_url` in `app/grounding.py` is the owner's comparison rule. It also returns nothing for anything but http and https, because the rule ignores the scheme, and a `javascript:` URL could otherwise match a source and reach a link's `href`. `NewsGrounder.validate(answer, seen_ids, web_urls)` removes unmatched web citations, then applies the existing checks: strict for items, and an answer with no citations at all still fails. An answer whose only citations were removed is kept. The URL stored is the one the model cited.
- **Orchestrator:** `_NewsChatAgent` overrides `validate` (and logs how many were removed, no URLs), `data_parts` and `citation_rows`. A web part is `{chunkId: url, citationIndex, excerpt, kind: "web", title, url}`. Item parts don't change.
- **Streaming, from reading the orchestrator:** there is no model streaming. `run_turn` awaits `agent.run()` in a task, forwards status labels from a queue, then sends the finished, grounded text and data parts through `iter_grounded_stream`. So the tool's parts are only read from the finished run, as in the live check, and untested model streaming doesn't apply. The one consequence: web search runs inside the provider and emits no status, so the label stays "Reading your AI newsletters" during a search.
- **Storage:** `email_citations` gains nullable `web_url` and `web_title`; `ck_email_citations_one_target` becomes `num_nonnulls(email_chunk_id, news_item_id, web_url) = 1`. `insert_email_citations` checks the same. Hand-written migration on `b7f3a2c9e154`. Autogenerate sees the two columns, not the check, so the migration changes the check by hand. Downgrade deletes web rows, which the narrower check can't hold.
- **Frontend:** `CitationData.kind`, `citationKind` returns `web` on it, a `WebDetails` component (URL and "Open page"), the panel's title from the citation, and a chip label of `Web · host`. Old parts have no `kind` and take the same paths as before.
- **Privacy page:** OpenAI's entry says news questions may go to OpenAI's web search; date 7 November 2026.

Tests (red first): `tests/grounding/test_news_web_citations.py`, `tests/news_assistant/test_web_search.py`, `tests/news_assistant/test_news_agent_turn.py`, `tests/database/test_email_citations.py`, `tests/news_assistant/test_news_instructions.py`. No frontend tests, per `frontend/AGENTS.md`.
