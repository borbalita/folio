# 003/01 — Demo user, access, demo mailbox and bank

## Goal
A user named by `DEMO_USER_ID` can open Finance, and owns a demo mailbox and a demo bank account that no cron touches.

## Scope
- `demo_user_id` in `config.py`, optional; the owner sets `DEMO_USER_ID` on Railway.
- Finance access: owner or demo user (`is_finance_owner` becomes a Finance-user check; the agent list and every Finance route follow it).
- A `require_demo_user` dependency for `/finance/demo/*`: 403 for anyone but the demo user; 404 when `DEMO_USER_ID` is unset.
- Mailbox provider `demo` (model enum, check constraint, autogenerated migration). Demo mailboxes don't count for Email access.
- A function that creates the demo mailbox, bank connection `Demo Bank` and account "Girokonto" (fake IBAN, consent valid for years) when missing; reset (003/03) calls it.
- Bank sync and expiry notices cover only N26, ING and PayPal. The demo user's Accounts page lists only the demo bank; Connect returns 403 for the demo user.

## Out of scope
- Data in those accounts (003/03).

## Acceptance criteria
- Given `DEMO_USER_ID`, when the demo user calls `/me`, then the agents are `documents` and `finance`, not `email`. (test)
- Given the demo user, when they call a Finance route, then it answers; given another user who is not the owner, then 403. (test)
- Given the owner, when they call a `/finance/demo` route, then 403. (test)
- Given no `DEMO_USER_ID`, when anyone calls a `/finance/demo` route, then 404, and the owner's Finance works as before. (test)
- Given the demo accounts exist, when the email or bank cron runs, then it doesn't read or change them. (test)
- Given the demo user, when they list bank connections, then only the demo bank appears, connected; when they press Sync now, then nothing is fetched and no error is returned; when they start a connection, then 403. (test)

None.
