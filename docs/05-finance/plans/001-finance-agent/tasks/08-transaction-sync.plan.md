# 001/08 — Transaction sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Booked transactions from the N26 main account, ING and PayPal are stored without duplicates, three times a day by cron and on demand from the accounts page.

**Architecture:**
- The Enable Banking client gains `fetch_transactions`. It follows `continuation_key` through every page and returns only booked entries, parsed into `EbTransaction`.
- A pure function gives each entry a `dedup_key`, and `transactions` has a unique `(account_id, dedup_key)` constraint. Inserts use `ON CONFLICT DO NOTHING`, so the 7-day overlap window and repeat runs store nothing twice.
- `sync_all(user_id)` walks the owner's connected accounts. The cron CLI `python -m ingest.bank` and the API's Sync now both run it inside `run_job("bank_sync", …)`.

**Tech Stack:** FastAPI, httpx (async), SQLAlchemy + Alembic, React + TS. No new dependencies.

**Spec:** [../README.md](../README.md) (Decisions, Design, Key concepts, Risks), task [08-transaction-sync.md](08-transaction-sync.md), API facts and real-data findings in [../research.md](../research.md).

## Global Constraints

- Endpoint: `GET /accounts/{uid}/transactions` with `date_from` (YYYY-MM-DD) and `continuation_key`. The response is `{"transactions": [...], "continuation_key": str | null}`. Keep fetching while `continuation_key` is non-empty.
- Store only `status == "BOOK"`. `credit_debit_indicator` is `CRDT` (positive) or `DBIT` (negative). Any other value is an `EnableBankingError` (validate at the boundary).
- Booking date is `booking_date`, falling back to `transaction_date` (PayPal has only that one).
- Counterparty: `creditor` / `creditor_account.iban` for debits, `debtor` / `debtor_account.iban` for credits. Remittance text is `remittance_information` joined with `"\n"`.
- `date_from` per account: the latest stored `booking_date` minus 7 days, or today minus 90 days when the account has none.
- Deduplication: with an `entry_reference`, the key is `ref:{CRDT|DBIT}:{entry_reference}`. Otherwise it is `fb:` + sha256 hex of `date|amount|counterparty name|counterparty IBAN|text|n`, where `n` is the ordinal (0, 1, …) among this run's fallback rows with that identical tuple.
- Sync now is refused with 429 when any `bank_sync` job run started in the last 10 minutes (cron runs included).
- Connections without a session or past `valid_until` are skipped (counted, no API call). An error on one account doesn't stop the others. The run then raises at the end, so the job-run row is `failed` and names the banks.
- Cron is `0 4,11,18 * * *` (UTC), start `python -m ingest.bank`, restart policy `NEVER`.
- Every new table enables RLS in its migration and is listed in `RLS_TABLES`. The migration is autogenerated, with RLS added by hand.
- JSON responses use camelCase keys. Amounts go out as strings (Decimal), not floats.
- No transaction content in logs: log counts, banks and statuses only.

## Review Focus

1. **The overlap window crosses a day with identical N26 rows.** All of that day's rows are fetched together, because `date_from` is a whole day. Ordinals are computed over the whole run (all pages), not per page, so a page break inside a day doesn't change keys. Test: identical rows split across two pages keep keys 0 and 1 (Task 2).
2. **One bank fails (expired consent, 401, 5xx).** The other accounts are still stored. The job row is `failed` with `"ING: Enable Banking returned 401"`, and the cron exits non-zero. Test in Task 3.
3. **Sync now is pressed twice quickly, or while the cron runs.** The second press gets 429 with "Synced less than 10 minutes ago; try again later." Test in Task 4.
4. **A connection whose consent has expired** isn't called (that would waste the unattended quota and fail) and shows up as `skipped`. Test in Task 3.
5. **Sync now counts as the owner being present.** It sends `Psu-Ip-Address` (first `X-Forwarded-For` hop, else the client host) and `Psu-User-Agent`, so it doesn't use up the four unattended reads. If Enable Banking answers `PSU_HEADER_NOT_PROVIDED`, the manual check reveals it; record it in the spec. Test of the headers in Task 1.

**Interfaces:**
- Consumes: `EbTransaction` (Task 1).
- Produces:
  - Model `Transaction` (`transactions`): `id` uuid pk; `account_id` FK `bank_accounts.id` ON DELETE CASCADE; `booking_date` date; `amount` `Numeric(14, 2)`; `currency` `String(3)`; `counterparty_name`, `counterparty_iban`, `remittance`, `bank_code`, `entry_reference` Text nullable (`remittance` not null, default `""`); `dedup_key` Text; `raw` JSONB; `created_at`. ### Task 3: Sync all accounts, cron CLI, Railway service

**Files:**
- Create: `backend/app/finance/transaction_sync.py`
- Create: `backend/ingest/bank/__init__.py`, `backend/ingest/bank/__main__.py`

- Test: `backend/tests/finance/test_transaction_sync.py`, `backend/tests/ingest/bank/test_cli.py`

**Interfaces:**
- Consumes: `fetch_transactions` (Task 1); `store`, `latest_booking_dates` (Task 2); `run_job` (`app.database.job_runs`).
- Produces:
  - `class BankSyncFailed(Exception)`: its message is `"; ".join("{bank}: {error}")`.
  - `@dataclass(frozen=True) class SyncAccount`: `id: uuid.UUID`, `uid: str`, `bank: str`; plus `def sync_targets(user_id) -> tuple[list[SyncAccount], int]` in `app/database/bank_connections.py`, giving accounts of live connections and the number of skipped connections (no session, or `valid_until <= now`).
  - `async def sync_all(user_id: uuid.UUID, *, today: date, psu_headers: dict[str, str] | None = None) -> dict[str, int]`: returns counts `accounts`, `fetched`, `added`, `skipped`. Raises `BankSyncFailed` after storing every account that worked.
  - `def run_bank_sync(user_id: uuid.UUID, psu_headers: dict[str, str] | None = None) -> dict[str, int]`: `run_job("bank_sync", lambda: asyncio.run(sync_all(...)))`. Synchronous, so the API calls it through `asyncio.to_thread`.
  - CLI `python -m ingest.bank`: needs `FINANCE_OWNER_USER_ID` and the Enable Banking settings (exit 1 with the names when missing, like `ingest.email`). It configures logging and tracing like `ingest.email.run.main`, runs `run_bank_sync`, and prints the counts.
